Cursor 这个夏天动作不断。6 月 SpaceX 宣布收购它，8 月 15 日正式完成；今天它又推出了自己的代码托管服务 Origin，说要替代 GitHub。

这几件事，我的感觉是：离我很远。

## 我用过 Cursor 一阵

Cursor 我用过几个月，后来换成了 Claude Code。

换走的主要原因是模型效果。那几个月里，同样的活，Claude Code 做出来的东西更合我的意，慢慢就用它多了，Cursor 也就不在我的日常里了。

所以它被谁收购，要不要自建托管，对我的工作没有直接影响。

## 几个月的 Cursor

Cursor 我用了几个月，不算短。

那几个月，它是我的主力编辑器。它好用的地方，用过的人都知道。换走以后，有些习惯跟到了 Claude Code 里，有些就放下了。

所以说它离我远，不是说我不了解它，是它已经不在我每天的路上。一个用过几个月的工具，被收购的消息看起来，会比一个没用过的更有感觉一点，但也就是一点。

## 换走的原因，是模型

从 Cursor 换走，原因是模型效果，这一点现在回头看挺有意思。

Cursor 是一个编辑器，它的模型是接别人的。我换走的时候，觉得自己是在换编辑器；其实换的是编辑器后面的那个模型。编辑器本身好不好用，在模型效果面前，排到了后面。

模型效果这件事变得很快。今天因为模型换走，明天也可能因为模型换回来，只要它接上了更好的那一个。

这也能解释它这个夏天为什么动作不断。一个靠别人模型的编码工具，最怕的就是用户发现，自己真正在意的是模型。被收购、自建托管，都像是在给自己找一些不靠模型的东西。

## 代码在 GitHub

我个人项目的代码都在 GitHub。研报笔记 Agent，几个自己用的小工具，都在上面，部署放在 Vercel。

Cursor 说要替代 GitHub，我的第一反应是，这件事不会碰到我。一个编码工具想接管代码托管，要让用户把代码搬过去，这比做一个好用的编辑器难得多。代码放在哪，牵涉的是协作的习惯、自动化的流程、部署的链路。我的个人项目就是往 GitHub 推送以后自动部署的，换托管，等于这一整条链都要重接。

## 离我远，因为我知道第二天用什么

离我远，不是因为我觉得这种事不会轮到自己，是因为真轮到了，我知道怎么办。

如果常用的编码工具突然不能用，我第二天会回到 Claude Code 接着干。它是我手上最稳的那个底。底稳，其他的换来换去都不慌。

今年用下来，编码工具对我已经是可以换的：额度见底的时候，我换过工具接着干。那几次换工具，就像一次次小演习。项目的规则写在项目里的文件里，换一个工具，读一遍就能接上。

所以 Cursor 被收购、要自建托管，在我这里是新闻，不是风险。

## GitHub 加 Vercel，这条链不想动

我的个人项目，代码在 GitHub，部署在 Vercel。推送上去，Vercel 自动构建、上线。

这条链用了很久，很顺。它顺，是因为 GitHub 和 Vercel 之间接得好，推送、预览、上线，中间不用我操心。

Cursor 做 Origin，想替的是 GitHub 这一环。可对我来说，GitHub 不是一个单独的东西，它连着 Vercel，连着我所有项目的历史。换掉它，要重接的是整条链。一个编码工具要让我动这条链，得给出一个比这条链还顺的理由。

## 一个工具想把能拿的都拿回来

不过把这几件事放在一起看，还是能看出点东西：一个编码工具，靠别人的模型，靠别人的托管，现在想把能自己拿的都拿回来。

被收购，意味着方向不再完全由它自己定；自建托管，意味着它不想把用户的代码留在别人那里。站在它的位置上，这些都说得通。

站在用户的位置上，我只关心两件事：我的代码在不在我手里，换一个工具要付出多少。现在这两件事都没问题，所以它离我远。哪天有问题了，它就近了。
