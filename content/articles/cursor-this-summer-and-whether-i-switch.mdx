Cursor 这个夏天动作不断。6 月 SpaceX 宣布收购它，8 月 15 日正式完成；今天它又推出了自己的代码托管服务 Origin，说要替代 GitHub。

这几件事，我的感觉是：离我很远。

## 我用过 Cursor 一阵

Cursor 我用过一阵，后来换了。

换的原因很普通，别的工具用着更顺手，习惯就跟过去了。Cursor 已经不在我的日常里。

所以它被谁收购，要不要自建托管，对我的工作没有直接影响。

## 代码在 GitHub

我个人项目的代码都在 GitHub。个人网站，研报笔记 Agent，几个自己用的脚本，都在上面。

Cursor 说要替代 GitHub，我的第一反应是，这件事不会碰到我。一个编码工具想接管代码托管，要让用户把代码搬过去，这比做一个好用的编辑器难得多。代码放在哪，牵涉的是协作的习惯、自动化的流程、部署的链路。我的网站就是往 GitHub 推送以后自动部署的，换托管，等于这一整条链都要重接。

## 离我远，因为我知道第二天用什么

离我远，不是因为我觉得这种事不会轮到自己，是因为真轮到了，我知道怎么办。

如果常用的编码工具突然不能用，我第二天会用 Claude Code 接着干。

今年用下来，编码工具对我已经是可以换的：额度见底的时候，我换过工具接着干。项目的规则写在项目里的文件里，换一个工具，读一遍就能接上。

所以 Cursor 被收购、要自建托管，在我这里是新闻，不是风险。

## 一个工具想把能拿的都拿回来

不过把这几件事放在一起看，还是能看出点东西：一个编码工具，靠别人的模型，靠别人的托管，现在想把能自己拿的都拿回来。

被收购，意味着方向不再完全由它自己定；自建托管，意味着它不想把用户的代码留在别人那里。站在它的位置上，这些都说得通。

站在用户的位置上，我只关心两件事：我的代码在不在我手里，换一个工具要付出多少。现在这两件事都没问题，所以它离我远。
