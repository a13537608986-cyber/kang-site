最近做完了一个小东西，叫研报笔记 Agent。把行业报告的 PDF 丢进去，它帮我整理成小红书那种图文笔记的样子：几个标题可选，一段正文，一组标签，再从报告里挑几页做成图片。

## 几个晚上，用 Claude Code

做它花了几个晚上，基本是用 Claude Code 写的。

我写得出需求，写不好代码。以前也有过类似的想法，到了要动手那一步就停了。这次是我说要什么，它来写；跑起来不对，我告诉它哪里不对，它再改。几个晚上下来，东西能用了。

做它的原因很简单，我自己要用。平时看报告，想把有用的部分记下来，又懒得一页页截图、排版。做一个工具，比每次手动做省事。

## 最难的一步，是同步到小红书

几个晚上里，最难的不是整理报告，是最后一步：同步到小红书。

整理这部分，说清楚要什么，改几轮就对了。同步不一样。小红书的编辑页是一个网页，要把标题、正文、标签、图片一样样放进去，图片的顺序要对，有时候还要设定时间。网页结构一变，前面做好的就对不上了。

这一步我来来回回改了好几次。它也让我明白了一件事：自己用的时候，坏了我知道怎么回事，改一下就行；如果别人在用，每一次网页变动，都是一次别人来问我怎么用不了。

## 每周一两份，偶尔发出去

现在每周用它整理一两份报告。第一份拿它整理的，是一份 AI 行业报告。

几十页的 PDF 丢进去，出来一份笔记和几张图。标题写得有时候像营销号，我会改；正文会把核心数字和判断拎出来，比我自己读完随手记的整齐。

整理好的笔记，偶尔会发到小红书上。大多数时候不发，只是自己留着，算是读过这份报告的记录。

## 朋友问我要

后来和朋友聊起来，朋友看了几份我整理出来的笔记，问能不能也给用用。

我想了几天，决定不做成产品。

不是因为它不好。它在我这里跑得挺顺，我也一直在用。不做成产品，是因为一旦要给别人用，事情就变成另一种：要考虑别人的报告长什么样，要处理各种格式，要写说明，要回答问题，还要跟着小红书的页面变化去改。同步那一步我自己改了好几次，换成别人在用，每一次都得是我去修。

这些事在工作里我每天都在做，回到家不想再做一遍。

## 做一个东西，和维护一个产品

喜欢做一个东西，和喜欢维护一个产品，是两回事。前者是几个晚上的事，后者没有尽头。

做产品做久了，会下意识把每个做出来的东西都往成果上推：有人要，就该给；给了，就该做好；做好了，就该有更多人用。这条链每一步都顺，顺到最后，一个几个晚上的小东西，变成了一份长期的承诺。

所以它就放在这里，给自己用。哪天想改就改，不想改就不改。这一次，我想留一个例外。
