这周 Claude 的付费计划改了，编程用量变成月度额度。前两天还加了一个 Agent View，可以把多个任务并排管。

我天天用 Claude Code，用得最多的是给自己写小工具。以前是想到就开，改一个字也开，让它跑一遍看看也开。额度制以后，开之前得先想一下。

## 改制之前，偶尔碰到过上限

改制之前，我偶尔会碰到用量上限。碰到了，等一阵就好，不太影响节奏。

所以额度这件事，不是突然冒出来的。只是以前的限制是一阵一阵的，碰到了停一会儿；现在是一个月一个总数，用掉了就是用掉了。前一种让人等，后一种让人算。

等，是被动的，等完接着用，用法不用变。算，是主动的，每开一个会话，都在花一个月里的一份。

## 会话从十几个变成五六个

最直接的变化是会话少了。以前一天开十几个，现在五六个。

少掉的那些，回头看大多是不必要的。一行的修改，自己改更快，还不用等。问题问到一半发现自己没想清楚，关掉重开。一个任务做到一半，换个思路再开一个。这些以前不心疼，现在每一个都在花额度。

小工具的活，尤其容易这样。需求在脑子里，边做边想，想到一点开一个会话，做着做着又改主意。以前这么做没成本，现在得先把要什么想清楚。

## 同时跑的没少

有意思的是，同时跑的任务没有少，还是三四个。

会话少了，并行没少，看起来矛盾，其实是用法变了。以前的十几个会话是一个接一个开的，很多只是试探，开了很快就关。现在的五六个，每个都是想清楚了才开，开了就让它跑得长一点。所以同一时间挂着的，还是三四个。

Agent View 在这里帮上了忙。三四个任务并排放着，哪个在等我确认，哪个跑完了，一眼能看到，不用在几个窗口之间来回切。

## 规则写进了 CLAUDE.md

变化最大的一件事，是我把规则写进了 CLAUDE.md。

以前每开一个会话，开头都要交代一遍，交代得最多的是风格：代码按什么习惯写，文字要写成什么样。说一遍就要花掉一轮来回，而且每次说得不完全一样，它做出来的东西也就不完全一样。

额度制以后，这一轮来回开始让人心疼。于是把这些写成一份 CLAUDE.md 放在项目里，它每次开会话自己去读。

写得最多的，还是写作和代码风格。这类要求有个特点：单拿出一条都不复杂，但每一次都要，少说一次就会走样。正适合写下来。

写下来以后，会话开头的交代省了，做出来的东西也更一致了。会话能从五六个里挤出三四个并行，这份文件是前提之一。

## 月底换 Codex，顶一周左右

算着用，还是会有不够的时候。月底额度见底，我就换 Codex 顶上，一般要顶一周左右。

一周不算短，等于一个月的额度，我大概用三个星期。

对我手上这些小工具来说，两个都能做。所以额度用完不是停工，是换一个工具接着干。

规则写成文件，在这里又帮了一次。风格要求已经写下来了，换到 Codex，照着给它就行，不用凭记忆重新说一遍。

这件事让我意识到一个以前没想过的问题：我的工作流里，编码工具其实已经是可以替换的了。以前只用一个，是习惯，不是非它不可。能替换的前提，是那些要求不在我脑子里，而在文件里。

## 换过去的那一周

换到 Codex 的那一周，活没停，但做法会跟着变一点。

两个工具各有各的习惯，同一件事，给的说法、做出来的样子，总有些差别。这时候规则文件的用处更明显：差别落在它们各自的发挥上，不落在我要的风格上。

一个月里三个星期用这个、一个星期用那个，时间长了，两边各自适合什么活，大概会慢慢看出来。这是额度逼出来的比较，以前只用一个，没机会比。

## 心疼一下，用法反而对了

额度让我心疼了一下。心疼的结果是：不必要的会话少了，想清楚再开，规则写下来，额度见底有备用。

这几件事，本来就是用这类工具该有的方式。以前不这么做也能用，是因为不用算。现在要算了，反而把该做的事做了。
