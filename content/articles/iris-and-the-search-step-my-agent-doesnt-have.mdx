今天小红书开源了一个 Search Agent 模型，叫 Iris，35B 和 397B 两个版本，同量级里成绩领先。

## 找报告，靠我自己搜

研报笔记 Agent 现在没有搜索这一步。报告是我自己搜到的，下载下来丢进去，它负责整理成笔记。

找报告这件事一直是手动的：想看哪个方向，去搜，翻几页结果，挑出像样的，下载，再来。搜得顺的时候几分钟，不顺的时候，半天找不到一份靠谱的。

所以看到 Iris，第一个念头是加一步：给它一个方向，它去找最近的报告，找到了直接进整理流程。

## 前几天，发现有朋友在用

前几天写钢人论证那篇，结论是先别再加功能，先弄清楚有没有真实用户。

这几天有了一点进展：有朋友在用它。之前朋友问我要过，这次是真的在用，拿它整理自己在看的报告。

一个真实用户，不多，但和没有是两回事。这让我对要不要加搜索这件事，比前几天更犹豫了。

## 想先试试效果

看到 Iris，我的第一反应是想先试试效果。

不是马上加进去，是先单独试：拿几个我最近搜过的方向给它，看它找回来的报告和我自己搜的比，是好是差。好，搜索这一步就有了一个现成的方案；差，就不用想了。

试一下不花多少时间，也不动研报笔记 Agent 本身。

## 最担心的是越做越像产品

可我最担心的，不是它效果好不好，是加上以后，这个东西越做越像一个产品。

研报笔记 Agent 一开始，是几个晚上做给自己用的。开源以后，有了仓库；朋友用了，有了用户；如果再加上搜索，它就从一个整理工具，变成了一个从找到整理全包的东西。每一步都顺，顺下来，离我去年说的只给自己用越来越远。

钢人论证那次，我答的是没人用就停。现在有人用了，停的理由弱了一点。可有人用，和我愿意把它当产品维护，还是两件事。

## 先试，不加

所以现在的决定是：Iris 先试，不加。

试的结果留着。等朋友那边用上一阵，看是不是真的缺搜索这一步，再说。如果缺的是朋友，那是一个产品的问题；如果只是我自己想加，那就还是几个晚上的事。
