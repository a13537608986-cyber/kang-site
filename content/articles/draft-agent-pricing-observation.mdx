## 三种定价模式的观察笔记

先说结论：Agent 产品目前没有一种定价模式是稳定的，市面上能看到的方案本质上都是过渡形态。

按席位收费继承自 SaaS 时代，好处是客户的预算流程认这套逻辑，坏处是它和 Agent 的价值逻辑相悖——Agent 做得越好，需要的人越少，席位数反而下降。一个替代了重复性工作的产品，用"人头数"计价，等于亲手给自己的收入设了天花板。

按用量收费（token、任务数、运行时长）对厂商更诚实，成本和收入挂钩，不会被重度用户拖垮毛利。但它把不确定性转嫁给了客户：采购方在签合同前算不出这个月要花多少钱，财务审批就过不去。我的观察是，纯用量计费的 Agent 产品在中大型客户那里普遍卡在采购环节，最后不得不加一层"预购额度包"来伪装成固定支出。

按结果收费听起来最性感——解决一张工单收一笔钱，转化一个线索分一笔成。问题在于归因。结果是 Agent 单独完成的，还是人机协作完成的？失败的任务算谁的？目前敢用这种模式的，基本都是结果边界极其清晰的窄场景（比如客服工单关闭），通用型 Agent 暂时玩不动。

目前我倾向的判断：未来两三年大概率是"席位保底 + 用量阶梯"的混合形态占主流，按结果收费只在少数可严格归因的场景里成立。这一段还需要补充更多公开案例再展开。
